Technical spec

Give it a floor plan and, if the apartment exists, photos or a scan. Build a room you recognise, then talk through what to change.A developer's unbuilt apartment starts from the plan alone. Project name is undecided.

The architect

Builds the shell and hands furniture pieces to subagents. They match the photos using Blender scripts they can change, rather than settling for generic furniture.

It can ask for more photos before starting. Builders can ask too. The architect combines requests and shows where to stand; other builders keep working.

The designer

Gets the room and your needs, without the build history. Uses Pinterest references or screenshots and a real catalog to suggest layouts and prices.

Remembers what stays and what needs a home, including books and drawer contents. Works on options until you accept one.

You can talk to either agent while it works, correct it, or edit the room yourself. Voice is still a scope decision.

What we build

Codex SDK, regular subagents, scripts and skills. Scripts handle Blender, renders, scene edits, fit checks and prices. Skills capture mistakes from our room project so agents don't repeat them.

Scene JSON holds object IDs, sizes, placement, attachments, references and user needs. The web app shows the room, chat and pending questions. A finished mesh must not undo a newer user edit.

How we test it

Furniture: use photos with known sizes; hold back another angle. Compare builds with and without starter scripts. People vote on which looks closer.

Rooms and designs: code checks fit, door access, storage and budget. People check the photo match and compare layouts. Track time, tokens and corrections; turn failures into tests and keep some examples unseen.
